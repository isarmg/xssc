# 9. 发行信任与操作

依赖、完整源码提交、软件版、目标平台和状态合同共同绑定发行身份。Cargo 使用官方 URL、完整提交修订、精确版本与根锁文件。工具只依赖 xcsc 单体 1.0.3，启用 `offline-maintenance` 特性；通过客户端公共文件能力读取服务器状态，服务自身的严格属主校验保持不变。

发布者用 `stage-upgrade-release.py` 对真实目标、产品定义、独立受信任公钥和受控私钥制作离线签名包。清单的精确字节参与签名，ELF 与完整树摘要都在签名范围内。接收者从独立渠道固定公钥 DER 指纹。

工具自身 `stage-release.sh` 只在源码无未提交更改、软件标签与锁定依赖的发行构建一致后暂存；定稿脚本核对实际身份和源公钥，签名、解包并运行 `support` 自验证。私钥不进入制品。

本地提交和标签、离线缓存验收与远端公开发布分别记录。尚未推送的完整 Git 对象不能证明正式独立 CI 可从远端取得。本轮不重写已封存的历史标签或资产。

操作失败先保留恢复目录并执行检查；交接后只有明确授权丢弃新增写入才恢复，最后验证实际原程序的业务就绪。详见[操作文档](../operations.md)。
