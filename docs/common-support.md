# xssc 的公共支撑职责与单体依赖

本项目属于 **客户端**，Rust 公共支撑只依赖 **`xcsc` 一个包**。公共代码物理合并在该包的 `src/` 内部模块；本项目直接使用这些模块，没有拆分子包或入口包装包。

| 公共包 | 职责 | 平台范围 | 分发方式 |
|---|---|---|---|
| `xcsc` | 客户端公共支撑，包括升级工具 `xssc` 的离线维护能力 | 模块按需支持 Linux、Windows、macOS、Android、iOS；本产品实际支持以部署文档和发行附件为准 | 一个 Rust Cargo 包 |

包名、仓库名、软件版本和内部模块是不同概念。`xcsc::runtime` 和 `xcsc::log` 表示同一个包内的模块，不代表独立依赖包。公共包版本为 `1.0.3`；业务数据合同、UUIDv4、IPv4/IPv6、第三方软件版本及系统 API 名称遵循其实际含义。

## 依赖如何固定

根或子目录 `Cargo.toml` 固定官方 Git URL、完整 40 位 `rev` 和 `version = "=1.0.3"`；`Cargo.lock` 固定该源与依赖摘要，两者一起更新。临时本地覆盖用于联调，正式 CI 与发行构建使用固定官方源码。业务协议类型保持独立的数据合同。

## 客户端能力

普通客户端从 `xcsc::runtime`、`xcsc::cli`、`xcsc::fs_safety`、`xcsc::secret`、`xcsc::secret_envelope`、`xcsc::secure_xml` 和 `xcsc::log` 等内部模块取得实际需要的能力。桌面 CLI、移动 FFI 和平台文件保护保留各自的调用边界。

安装、配对、重新配对、启动停止、状态查看、问题诊断和卸载，以本项目[部署指南](platform-setup.md)为准。公共库没有独立服务、配对码或卸载器；工具无需配对的情形也在部署指南中明确说明。

- `mobile-ffi` 启用移动 C ABI；`jni` 同时启用它并提供 Android JNI 入口。C 数据布局、状态码、结果释放规则和原生符号保持既定合同。
- `tracing` 启用客户端结构化日志适配；日志实现与错误类型来自 `xcsc` 自身。
- `offline-maintenance` 是同一包内的显式 Linux 离线维护能力，用于 `xssc` 的发行身份、私有状态文件、文件保护和 SQLite 维护；普通移动构建不启用该模块。

## 查看依赖与排查

从仓库根目录执行 `cargo tree --locked -e normal` 查看实际运行依赖。`cargo metadata --locked --no-deps --format-version 1` 列出本项目 Cargo 包、目标和声明的依赖，可核对 `rev` 与特性；完整传递关系仍由 `cargo tree` 查看。这两个命令读取构建信息，不执行安装或配对。

更新公共包时同步源码提交修订、Cargo 锁、调用代码和发行输入。遇到找不到内部模块、提交修订不匹配或锁文件完整性错误，先核对这些输入是否属于同一次发布；最终可部署性由本项目当前源码的原生 CI 与实际发行制品验收证明。
