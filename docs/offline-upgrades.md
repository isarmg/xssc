# 固定 ROOT 升级合同

## 执行升级

XSSI `upgrade.sh --root ROOT --version N.N.N` 使用精确稳定 tag，下载唯一的 `{product}-{version}-linux-x86_64.tar.gz`。完整SHA256清单验证及实际加载的 systemd 单元路径和字节检查在停服前完成。任何网络、SHA256、权限或目标身份失败都不停止当前服务。

六个 server 只暴露 `--root ROOT` 运行入口。配置、管理员、数据库、密钥和普通日志默认位于同一 ROOT；文件、视频及实例业务数据允许明确外置，systemd 单元位于系统目录。无 `current` 链接、版本目录或旧路径探测。

SHA256包的唯一格式是 [PackageManifest v1](reference/release-artifacts.md)。工具从源、目标SHA256包导出内部升级事务；内部事务对象不能作为另一种公共包格式提交。

源 `libexec/setup config-validate` 只验证配置并报告真实保护范围，不能替代数据库检查。计划的每个资源必须精确匹配辅助程序声明的最小根；不得扩大到祖先目录或添加无关资源。真实数据检查在完整快照之后进行，校验器的写入会被检测并拒绝。

源和目标辅助程序依据各自发行绑定的当前契约材料只读检查配置与数据。不同当前结构直接拒绝升级，不提供数据转换、迁移入口或服务参与的锁交接。相关writer的停止与启动控制由管理员工具和系统管理器负责。

程序替换只处理SHA256清单中的文件，删除源清单已经弃用的程序资源，不递归覆盖 ROOT 或外置业务文件。安装时创建的 systemd 单元必须使用固定 ROOT 和服务账号；当前升级要求源目标的 unit 模板与 writer 声明完全一致，改变单元合同的包在停服前拒绝，不能静默保留旧单元。升级不加入旧命令包装。

持久资源快照记录每个文件和目录的 UID、GID、权限、有界的 Linux POSIX access/default ACL，以及纳秒精度的修改时间。恢复在重建内容和设置所有者、权限之后还原 ACL，并清除原本不存在却在重建时继承的 ACL；最后恢复修改时间，逐项核验字节、权限和时间。共享目录的嵌套 default ACL 同样保留。校验器副作用比对涵盖所有持久文件和目录的修改时间，不在业务状态目录中写工具标记。此合同不包含访问时间、创建时间、`user.*` 或 SELinux 扩展属性。

预检先保存操作意图，再创建暂存目录并记录其父目录及自身的设备/inode。清理只处理本操作持久记录的目录；若在极窄的创建目录与记录 inode 之间中断，工具保留未知目录，不按路径名称推断删除权，需要管理员检查处理。

恢复校验完整快照和持久记录。XSSC 对全部 writer 的系统管理器条件限制、请求和实际状态保存持久 authority；中断后限制继续保持。可能出现业务写入后，不自动丢弃新增内容。恢复需要原事务身份并在恢复启动前保存可能出现写入的 intent。已完成材料按显式保留策略回收，未知 inode、引用和未完成事务均保留。详见[操作](operations.md)、[约束](development-contract.md)及[公共支撑](common-support.md)。
