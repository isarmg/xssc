# 功能、验证与取舍

`1.0.0` 只支持当前基线到未来同结构发行物。六个服务端使用统一机制；产品负责普通实际结构/资源诊断，本工具维护签名升级制品与部署定义。

| 功能 | 实现与证据 | 约束 |
|---|---|---|
| 来源可信 | Ed25519、独立 DER 信任锚、严格签名 DTO | 不信任包自带摘要或密钥 |
| 实际发行身份 | ELF/AMD64/摘要、封存目标 `release-identity` | 未绑定源码的程序只在明确的开发测试控制器中可用 |
| 部署合同 | 工具受签名的制品定义，单 ELF 或完整发行根目录 | 需要完整网页资源或配套进程的产品不能只升级二进制 |
| 完整发行根目录 | 精确模式/树摘要、不覆盖既有目录的发布、受控 `current` | 任意符号链接和未知 inode 拒绝 |
| 完整原组备份 | 程序、配置、数据、外置资源和发行根目录的全量清单 | 停服、持锁，WAL/SHM 同组保护 |
| 真实当前状态 | 源/目标只读 `config validate`、`state_paths` 覆盖 | 完全相同的 `SchemaIdentity`，变化合同明确拒绝 |
| 权限桥 | 行政文件 API、root 持有的执行目录、FD4、清组降权 | 服务不能写封存的 ELF 及祖先目录，DynamicUser 不支持 |
| UID/GID 恢复 | 逐项所有权、不跟随链接的文件描述符、`fchown` 和模式验证 | 不复制 ACL/扩展属性/硬链接关系 |
| 互斥与门 | 公共实例/维护锁、待恢复门、发行根目录部署协调锁 | 普通运行时严格核对实际有效用户 ID，不放宽 |
| 明确阶段 | 意图先持久、快照完备标记、原子切换 | 部分快照不用于恢复 |
| 中断恢复 | 依据事务日志、实际程序、发行根目录和备份校验恢复整组 | 未知状态不覆盖 |
| 新写入保护 | 交接前可能写入标记、显式 `--allow-data-loss` | 启动失败不证明没有写入 |
| 真实就绪 | systemd 的 MainPID/UID/执行文件摘要与正确服务的 HTTP 就绪结果 | 端口可连或进程存在不够 |
| 有界进程 | 标准输出和标准错误各 1 MiB，1–600 秒，超限终止并等待回收 | 标准错误不进入普通错误 |
| 有界快照 | 128 资源、128 深度、200万项/资源、默认 1 TiB 字节预算 | 精确输入与完整摘要仍有 I/O 成本 |
| 统一日志 | xcsc 的 `LogRecord`、安全码和操作 UUID | 不输出内部链或配置秘密 |
| 权威支持表 | 六个服务端的统一升级与恢复；公共库无独立服务运行时 | 不登记历史源码或推断数据版本 |

## 客户端公共能力

单个 xcsc 包固定官方 URL、精确 1.0.4 与完整提交修订，通过包内 contracts、state_file、fs_safety、log 和 sqlite 模块提供中立合同、权限、锁、原子文件和日志。工具实现阶段、恢复、信任与部署策略；产品普通诊断验证真实结构、完整性和业务约束。实际产品测试使用 SQLx 核对业务行。

## 已验证与未验证

自动机制测试覆盖签名、资源外漏、危险路径、完整树 Python/Rust 摘要一致、未知/损坏发行根目录、维修中断、实际服务 UID65534、验证器写入、启动失败与新写入保护。真实当前产品显式启用测试验证业务数据和实际运行时业务就绪，仅生命周期管理器为测试替身。

本地测试、绑定源码制品验收、真实 systemd 和正式远端 CI 分别报告。同一当前发行物重装不证明不存在的未来版本。软件版本和稳定数据格式身份分离；今后真实结构改变时才增加该发行的明确转换。

## 未纳入范围

本轮之前的旧格式升级、未知结构猜测、任意迁移钩子、零停机更新、DynamicUser、ACL/xattr/硬链接保留均未实现。保留数据优先于自动猜测恢复。预基线备份适配器因输入/结构合同不匹配删除，整组安全恢复由统一流程继续提供。
